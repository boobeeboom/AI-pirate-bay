  1. 1# Workshop Reservations
  2. 2
  3. 3Create workshops, share their links, and reserve seats. The product vision and vocabulary are in [product.md](docs/product.md); the accepted contract is in [behavior.md](docs/behavior.md).
  4. 4
  5. 5## Run
  6. 6
  7. 7Use the pinned Nix environment:
  8. 8
  9. 9```sh
  10. 10nix develop -c make run
  11. 11```
  12. 12
  13. 13With Go 1.27.1 or later already installed, use `make run`. Open [localhost:8080](http://localhost:8080).
  14. 14
  15. 15Data lives in `var/workshops.sqlite`. Restarting preserves the event history and rebuilds projections. Run one service process per database file. The product's unauthenticated access and visibility boundaries are described in [product.md](docs/product.md).
  16. 16
  17. 17To choose a listen address or database:
  18. 18
  19. 19```sh
  20. 20go run ./cmd/workshops -addr 127.0.0.1:8081 -db var/workshops_2.sqlite
  21. 21```
  22. 22
  23. 23## Development
  24. 24
  25. 25`make specs` runs the standalone, sequential spec runner (`go run ./cmd/specs`), printing failure details and a compact summary. `make check` runs those specs and infrastructure unit tests with the race detector, then vet and an executable build. Prefix either with `nix develop -c` when using Nix. Checks use isolated databases and need no running server.
  26. 26
  27. 27Every spec run validates `Covers` links against the accepted requirements. `nix develop -c go run ./cmd/specs -coverage` also reports each requirement's linked scenarios and outcomes after the full run.
  28. 28
  29. 29The application lives in `app/`, durable event types and decoding in `evt/`, the declarative specification model and verification in `spec/`, executable behavior scenarios in `specs/`, and application entry points in `cmd/workshops` and `cmd/specs`.
  30. 30

  32. 32- [Working modes](docs/modes/) contains piecemeal growth and document-writing guidance.
  33. 33- [Feature proposals](docs/features/) contains pending product changes.
