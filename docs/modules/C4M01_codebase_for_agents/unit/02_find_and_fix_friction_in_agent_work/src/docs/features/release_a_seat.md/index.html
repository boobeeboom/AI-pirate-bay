  1. 1# Release a seat
  2. 2
  3. 3Status: accepted — contract in `behavior.md` W13–W14; executable scenarios in `specs/release_a_seat.go`.
  4. 4
  5. 5## Intent
  6. 6
  7. 7A participant who can no longer attend should be able to release their seat, making it available to someone else.
  8. 8
  9. 9## Decisions
  10. 10
  11. 11- Release is idempotent: an unreserved email succeeds without an event, including a retry after release.
  12. 12- An existing reservation emits `SeatReleased`; the journal retains the original reservation. Replay removes only the matching workshop/email reservation from the projection.
  13. 13- Released seats can be reserved again by the same email or someone else. Availability, participant status, catalogue counts, and organizer lists derive from current reservations.
  14. 14- Command scenarios assert the durable event and redirect, or validation failure and no event. Page scenarios assert the resulting status, actions, counts, and lists separately.
