  1. 1# Documentation Rules
  2. 2
  3. 3Follow the spirit of Unix when working with the documentation in `docs/` and comments:
  4. 4
  5. 5- document only things and surprises that would surprise an experienced engineer that knows all about NixOS, golang, Make and building web products like that.
  6. 6- When asked to update `docs/` and comments - bring them in sync with the project, removing stale things, updating surprises and removing obvious things.
  7. 7- Prefer descriptive filenames for files in `docs/`, for they are more explanatory when used with `tree docs`
  8. 8- Assume that the reader knows how to use grep and follow the links. E.g. instead of documenting makefile step in markdown, just mention it, same with the code.
  9. 9- Remember that full doc tree is always loaded in the context at the start of each session. So in instructions refer to repository documents by filename in backticks when unambiguous in the doc tree, e.g. `prototype.md`. Otherwise use a repo-root-relative path without a leading slash, e.g. `docs/product/concepts.md`. Avoid Markdown links and `../` paths for these references.
  10. 10- no manual wrapping of lines in MD files.
  11. 11- no tables (unless asked)
